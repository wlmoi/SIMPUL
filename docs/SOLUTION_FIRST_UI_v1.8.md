# SIMPUL v1.8 — Solution-first UI and team credits

## Why the order changed
The original user problem is the evaluation of stopped/boarding vehicles near MRT Fatmawati without worsening mass-transit access. Revenue and API integrations are supporting features, not primary screen content.

## Landing page priority
1. One question and two immediate actions: diagnose obstruction, inspect corridor map.
2. Four action cards: diagnosis, map and field observation, A0/A1/A2 simulation, evaluation and decisions.
3. Evidence readiness with separate manual, interval, session, synthetic counts.
4. Schematic location panel and A0/A1/A2 explanation (no invented geospatial measurements).
5. Monitoring, classification, reporting and business as supporting modules.
6. About the Creators teaser, linking to the final `creators` route.

## Navigation
Desktop core: Overview, Diagnosis, Map, Observation, Simulation, Evaluation. Supporting routes remain grouped. Mobile bottom navigation: Overview, Diagnosis, Map, Simulation, Evaluation. Observation has a direct CTA in the first screen and the sidebar.
